## Context

After Git operations (branch, commit, push), the extension creates a pull request on GitHub using the `gh` CLI. The PR title comes from the spec title and the body includes a summary derived from the spec's context, requirements, and execution record.

## Requirements

### Functional
- `src/github/prCreator.ts` must export:
  - `createPullRequest(options: PrOptions): Promise<PrResult>` — creates a PR using `gh pr create`
  - `PrOptions` type: `{ specId: string; title: string; context: string; requirements: string[]; executionSummary: string; branchName: string }`
  - `PrResult` type: `{ success: boolean; url?: string; error?: string }`
  - PR body format:
    ```
    ## Spec: {specId}
    {context summary}

    ## Requirements
    {bulleted list of functional requirements}

    ## Execution Summary
    {tokens used, duration, test results}

    ---
    Generated by SDD Platform
    ```
  - `isPrCliAvailable(): Promise<boolean>` — checks if `gh` CLI is installed and authenticated
  - `linkPrToExecution(specId: string, prUrl: string): Promise<void>` — saves PR URL to the execution record

### Non-Functional
- Must handle `gh` CLI not installed → clear error with install instructions
- Must handle authentication failure → prompt user to run `gh auth login`

## Acceptance Criteria

### Automated
- [x] TypeScript compilation passes
- [x] Unit tests pass: PR body is correctly formatted from spec data
- [x] Unit tests pass: missing gh CLI returns appropriate error

### Manual
- [ ] PR is created on GitHub with correct title and body
- [ ] PR URL is saved to execution record

## Constraints
- Must use `gh pr create` CLI — do not use GitHub REST API directly
- Must use shell utility for all CLI commands
